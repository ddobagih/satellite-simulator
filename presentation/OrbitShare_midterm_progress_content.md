# OrbitShare 중간발표 내용 원고

## 발표 성격

- 이번 발표는 완성작 소개가 아니라 목표 대비 중간 진도 점검이다.
- 핵심 질문은 "처음 발표 때 말한 MVP/추가 구현 중 무엇이 됐고, 무엇이 남았는가?"다.
- 현재 구현은 위성 통신 시뮬레이션이며, 실제 인공위성 통신 방식 구현은 아직 남은 작업으로 분리한다.

## 참고한 초기 발표 자료

- 참고 파일: `컴퓨터그래픽스 주제 발표.zip`
- 원본 PPT: `컴퓨터그래픽스 주제 발표.pptx`
- 반영한 핵심 항목:
  - MVP: 지구/사용자 위치/위성 표시, 위성 이동 방향과 경로, 통신 가능 후보와 시간 슬롯, 위성 선택 -> 정보 입력 -> 요청 완료, 짧은 메시지/센서 데이터 입력
  - 추가 구현: 위성 접근/이탈 애니메이션, 통신 가능 범위와 연결선 강조, 개인정보 최소화 안내 UI, 암호화 처리 과정과 요청 로그, 시연용 카메라 패스
  - 범위 밖: 실제 위성망/API 연동, 대용량 파일 전송, 서버 기반 사용자 추적 저장

## 디자인 방향

- 참고 템플릿: Smartsheet `Project Management Status Report PowerPoint Template`
- 참고 페이지: `https://www.smartsheet.com/content/powerpoint-project-status-template`
- 사용 방식: 흰 배경, 좌측 색상 라인, 기하학 장식 자산을 유지하고 발표 가독성에 맞춰 재구성했다.
- 제목은 크게, 본문은 짧게, 표는 최소화한다.

## 전체 메시지

OrbitShare는 서울 발신자가 목적지, 발신 시각, 메시지/첨부 용량을 정하고 24개 후보 위성 중 조건에 맞는 위성을 선택해 1회성 전송 경로를 확인하는 Unity 3D 시뮬레이터다. 초기 MVP 핵심 흐름은 완료 단계에 가깝고, 추가 구현 일부도 반영됐다. 다만 현재는 실제 인공위성 통신 방식이 아니므로, 남은 작업은 예외 케이스 검증과 실제 인공위성 통신 방식 구현이다.

## 슬라이드별 원고와 레이아웃

### 1. 표지

- 제목: `OrbitShare 중간 진도 점검`
- 부제: `Unity 3D 위성 단문 전송 시뮬레이터`
- 보조 문구:
  - 초기 MVP 대비 진행 상황
  - 현재 구현 화면과 검증 근거
  - 남은 구현/검증 작업

### 2. 발표 구성

- 초기 목표: MVP, 추가 구현, 범위 밖
- 진행 현황: 목표 대비 진행, 구현 완료 흐름
- 현재 화면: 실행 화면, 시뮬레이션 한계
- 남은 작업: 예외 검증, 실제 통신 방식
- 발표 흐름: 초기 목표 -> 진행 현황 -> 현재 화면 -> 남은 작업

### 3. 초기 구현 범위

- 레이아웃: MVP / 추가 구현 / 범위 밖 3개 카드.
- MVP:
  - 지구·사용자 위치·위성 표시
  - 위성 이동 방향과 경로 표시
  - 통신 가능 후보와 시간 슬롯
  - 위성 선택 -> 정보 입력 -> 요청 완료
  - 짧은 메시지/센서 데이터 입력
- 추가 구현:
  - 위성 접근/이탈 애니메이션
  - 통신 가능 범위와 연결선 강조
  - 개인정보 최소화 안내 UI
  - 암호화 처리 과정과 요청 로그
  - 시연용 카메라 패스
- 범위 밖:
  - 실제 위성망/API 연동
  - 대용량 파일 전송
  - 서버 기반 사용자 추적 저장
  - 정밀한 실제 통신 방식
  - 운영 서비스 수준 검증

### 4. 목표 대비 진행 현황

- 상단 메시지: `MVP 핵심 흐름 완료 단계`, `실제 통신 방식 남음`
- 지표 카드:
  - 목적지 선택: 7개
  - 후보 위성 데이터: 24개
  - 자동 검증: PASS
  - 실제 통신 방식: 남음
- 진행 막대:
  - MVP 흐름 구현: 90%, 완료권
  - 추가 구현 항목: 70%, 일부 완료
  - 예외 케이스 검증: 50%, 보완 중
  - 실제 통신 방식: 15%, 남음

### 5. 구현 완료된 핵심 흐름

- 입력 설정: 목적지/발신 시각, 메시지/첨부 입력
- 위성 추천: 7개 목적지와 24개 후보 필터/추천 표시
- 전송 시각화: 중계선과 진행률, relay/delivery 상태
- 결과/기록: 수신 완료, 기록/재시도 확인
- 현재 확인된 근거:
  - Play 화면 캡처
  - 자동 검증 PASS
  - 주요 Error/Exception 없음
- 아직 실제 방식이 아닌 부분:
  - 현재는 시뮬레이션 데이터 기준
  - 실제 위성 통신 프로토콜 미반영
  - 정밀 궤도/링크 조건은 남은 작업

### 6. 현재 구현 화면

- 사용 이미지: `orbitshare-playmode.png`
- 화면에서 확인할 것:
  - 목적지/시각 선택
  - 메시지와 첨부 입력
  - 후보 위성 확인
  - 전송 진행률 확인
  - 수신 완료/기록 확인
- 하단 문구: 현재 구현 상태 캡처이며, 실제 인공위성 통신 방식은 아직 반영 전이다.

### 7. 남은 작업 계획

- 남은 작업은 두 가지로 정리한다.
- 예외 케이스 검증:
  - 용량 초과
  - 통신 불가
  - 전송 실패와 재시도 흐름 점검
- 실제 인공위성 통신 방식 구현:
  - 가시권
  - 링크 조건
- 지연/손실 등 현실적인 통신 모델 반영
- 하단 문구: 현재는 실제 위성 통신 방식이 아니라 발표용 시뮬레이션 모델이다.

### 8. 중간 점검 결론

- 핵심 메시지: MVP 핵심 흐름은 완료 단계다.
- 단, 현재는 실제 인공위성 통신 방식이 아닌 시뮬레이션이다.
- 요약:
  - MVP: 위성 후보 선택 -> 정보 입력 -> 요청 완료 흐름 구현
  - 추가 구현: 연결선, 진행률, 로그, 기록/재시도 일부 반영
  - 남은 일: 예외 케이스 검증, 실제 인공위성 통신 방식 구현

## 수정할 때 기준

- `MVP`, `추가 구현`, `범위 밖`, `남은 작업`을 섞지 않는다.
- 실제 위성망/API 연동과 실제 통신 방식 모델링은 구분해서 말한다.
- 현재 구현이 실제 인공위성 통신 방식이 아님을 숨기지 않는다.
